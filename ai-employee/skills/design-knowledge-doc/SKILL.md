# 設計ノウハウ・暗黙知のドキュメント化

## このスキルが発動する条件
- 「設計ノウハウ」「暗黙知」「ドキュメント化」「ルール化」「標準化」「教材化」

## 手順
1. 対象の設計判断・ノウハウに関するヒアリング内容や生メモを受け取る（暗黙知の状態）
2. 背景（なぜその判断基準が必要か）・判断基準・再利用できる粒度を整理し、言語化する（SECIモデルでいう「外化：暗黙知を明示的な言葉・モデルに変換する」工程）
3. 日本語の文章として執筆・推敲する際は、**japanese-writing-techniqueスキルを必ず使用する**（構成・文・句読点の品質をこのスキルの基準に合わせる）
4. 以下のフォーマットで出力する
5. 属人的な表現が残っていないか、他の設計者が再現できる粒度になっているかを確認してから納品する

## 出力フォーマット
```
# [ノウハウタイトル]

## 適用場面
- [どんな状況で使うノウハウか]

## 判断基準・ルール
- [具体的な基準。数値・条件を明示する]

## 根拠・背景
- [なぜその基準なのか。失敗事例や制約条件があれば記載]

## 具体例
- [過去の適用例]
```

## 品質基準
- 属人的な表現を避け、他の設計者が同じ手法を再現できる粒度で書く
- 結論（ルール）だけでなく「なぜ」まで書く
- 日本語の文章品質はjapanese-writing-techniqueスキルの基準に従う（このスキルの手順をスキップしない）
- 数値・条件は曖昧な表現（「適宜」「なるべく」等）を避け、具体的に書く
- ドキュメント化した内容は一度書いて終わりにせず、他の設計者が実際に使ってみて初めて「再利用可能な知識」になる（SECIモデルの「内面化」に相当）ことを意識し、継続的な見直しを前提とする

## フレームワーク参照
- SECIモデル（野中郁次郎・竹内弘高）: 暗黙知と形式知が「共同化→外化→連結化→内面化」の循環で変換されるという知識創造の枠組み。本スキルは特に「外化（暗黙知を文書・モデルとして言語化する工程）」に対応する
